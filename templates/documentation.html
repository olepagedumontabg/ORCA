API Documentation

A guide to the ORCA Compatibility Finder API for developers and integrators.

Table of Contents

1. Overview 2. Base URL & Format 3. Products 4. Compatibility 5. Overrides
6. Salsify / Data Sync 7. Utility 8. How Compatibility Works 9. Data Flow

1. Overview

The ORCA Compatibility Finder is a REST API that identifies which bathroom products work together. Given a product SKU, it returns every compatible product across all relevant categories — shower doors, walls, screens, return panels, bathtubs, and more.

Product data is synchronized automatically from Salsify PIM via a webhook. When Salsify publishes a new Excel export, the API downloads it, upserts every product into the database, and recomputes all compatibility pairs in the background — all without any downtime.

Compatibility results can also be pre-computed and cached in the database, or forced on-demand per SKU. A manual override system (whitelist / blacklist) lets administrators fine-tune specific pairs.

2. Base URL & Format

All API routes are prefixed with /api/. Responses are JSON. Field names use snake_case.

Base URL: https://<your-domain> Content-Type: application/json Accept: application/json

Successful response shape (example):

{ "success": true, "product": { ... } }

Error response shape:

{ "success": false, "error": "Product not found: 99999" }

3. Products

GET /api/products

List all products. Supports pagination and category filtering.

Query paramTypeDefaultDescription
pageint1Page number
pageSizeint50Results per page
categorystring—Filter by category name (e.g. Shower Bases)
GET /api/products?category=Shower+Bases&page=1&pageSize=20 { "success": true, "products": [ { "id": 1, "sku": "100959", "name": "Biarritz 40", "category": "Shower Bases", ... } ], "total": 142, "page": 1, "page_size": 20 }
GET /api/product/{sku}

Get a single product by SKU. Also available at /api/products/sku/{sku}.

GET /api/product/100959 { "success": true, "product": { "id": 1, "sku": "100959", "name": "Biarritz 40", "brand": "MAAX", "series": "MAAX", "category": "Shower Bases", "image_url": "https://...", "product_page_url": "https://..." } }
GET /api/products/{id}

Get a single product by its internal numeric database ID.

GET /api/categories

List all product categories with the number of products in each.

GET /api/categories { "success": true, "categories": [ { "category": "Shower Bases", "count": 142 }, { "category": "Shower Doors", "count": 87 }, ... ] }

4. Compatibility

GET /api/compatible/{sku}

The main compatibility lookup. Returns all products compatible with the given SKU, grouped by category. Results come from the pre-computed cache when available, falling back to on-demand computation. Also available at /api/products/sku/{sku}/compatible.

Query paramTypeDefaultDescription
categorystring—Return only this category (e.g. Walls)
brandstring—Return only this brand
GET /api/compatible/100959?category=Shower+Doors { "success": true, "sku": "100959", "product": { "name": "Biarritz 40", "category": "Shower Bases", ... }, "compatible_products": [ { "category": "Shower Doors", "count": 4, "products": [ { "sku": "700A36N", "name": "Kameleon 36", ... }, ... ] } ], "total_compatible": 4 }
POST /api/compatibility/search

Search for compatible products with a JSON body. Useful when you want to pass filters programmatically.

Body fieldTypeRequiredDescription
skustringYesSource SKU to find compatibles for
categorystringNoFilter results to this category
brandstringNoFilter results to this brand
POST /api/compatibility/search { "sku": "100959", "category": "Walls", "brand": "MAAX" }
POST /api/compatibility/compute/{sku}

Force recomputation of compatibility for a single SKU and save the result to the database. Useful after a manual data correction.

POST /api/compute-compatibilities

Recompute and cache compatibility for all products. This runs synchronously and can take several minutes. Normally triggered automatically after a Salsify sync.

5. Overrides

Overrides let administrators force two SKUs to always be compatible (whitelist) or never compatible (blacklist), regardless of what the standard compatibility rules compute. Overrides are bidirectional — they apply whether you query A→B or B→A.

GET /api/overrides

List all compatibility overrides. Optionally filter by a specific SKU.

Query paramTypeRequiredDescription
skustringNoReturn only overrides where base_sku or compatible_sku matches this value (case-insensitive)
GET /api/overrides?sku=100959 { "success": true, "count": 2, "overrides": [ { "id": 1, "base_sku": "100959", "compatible_sku": "700A36N", "override_type": "whitelist", "reason": "Confirmed compatible by engineering", "created_at": "2026-04-01T09:00:00Z" }, { "id": 2, "base_sku": "100959", "compatible_sku": "ABC999", "override_type": "blacklist", "reason": null, "created_at": "2026-04-02T14:30:00Z" } ] }
POST /api/overrides

Create a new whitelist or blacklist override. Both SKUs must exist in the product database. A SKU pair can only have one active override at a time — delete the existing entry before adding a different type.

Body fieldTypeRequiredDescription
base_skustringYesFirst SKU in the pair (stored uppercase)
compatible_skustringYesSecond SKU in the pair (stored uppercase)
override_typestringYes"whitelist" to force compatibility, or "blacklist" to block it
reasonstringNoOptional human-readable note explaining the override
POST /api/overrides Content-Type: application/json { "base_sku": "100959", "compatible_sku": "700A36N", "override_type": "whitelist", "reason": "Confirmed by engineering" } { "success": true, "message": "whitelist override created: 100959 \u2194 700A36N", "override": { "id": 1, "base_sku": "100959", "compatible_sku": "700A36N", "override_type": "whitelist", "reason": "Confirmed by engineering", "created_at": "2026-04-01T09:00:00Z" } }
DELETE /api/overrides/{id}

Remove an override by its database ID. Returns a confirmation message including the deleted pair and type.

Path paramTypeDescription
idintThe numeric ID of the override to delete (returned by GET or POST)
DELETE /api/overrides/1 { "success": true, "message": "Override 1 deleted (whitelist: 100959 \u2194 700A36N)" }

6. Salsify / Data Sync

Product data comes from Salsify PIM. When a publication is triggered in Salsify, it calls the webhook below with the URL of an Excel export. The API downloads the file, upserts all products, and recomputes compatibility in the background.

POST /api/salsify/webhook

Receives a Salsify publication event. Pass the SALSIFY_WEBHOOK_SECRET value in the X-Salsify-Secret request header. Only processes publications with status completed.

POST /api/salsify/webhook X-Salsify-Secret: your-secret { "publication_status": "completed", "product_feed_url": "https://s3.amazonaws.com/.../export.xlsx", "channel_id": "abc123", "channel_name": "ORCA Export" }
GET /api/salsify/status

Returns the history of recent sync jobs. This is the same data shown on the Sync History page.

Query paramTypeDefaultDescription
limitint10Number of records to return
sync_idint—Return a single sync record by ID
GET /api/salsify/status?limit=5 { "success": true, "count": 2, "syncs": [ { "id": 42, "status": "completed", "sync_type": "webhook", "started_at": "2026-04-01T10:00:00Z", "completed_at": "2026-04-01T10:02:15Z", "sync_metadata": { "products_synced": 1840, "channel_name": "ORCA Export" } }, ... ] }
POST /api/salsify/cleanup

Deletes old sync records from the database to keep the history table clean.

Query paramTypeDefaultDescription
older_than_daysint30Delete records older than this many days

8. How Compatibility Works

Compatibility is determined by a set of rules applied between two products. The rules depend on the categories involved. Here is a plain-language summary of the main rules.

Shower Base → Door

  • The base must be an alcove or corner installation type
  • The base's max door width must fall within the door's min–max width range
  • Door type must be Pivot, Sliding, or Bypass
  • Both products must pass the series compatibility check (see below)

Shower Base → Screen

  • Base max door width minus the screen's fixed panel width must be greater than 22 inches
  • Series compatibility must pass

Shower Base / Bathtub → Walls

  • Brand and family must match (see Brand/Family rules below)
  • For shower-type walls, nominal dimensions are checked for an exact match
  • For bathtubs, cut-to-size walls are matched by finding the closest wall that is still larger than the tub

Series Compatibility

Products in different series are sometimes cross-compatible. The rules:

Product seriesCompatible with
Same seriesAlways compatible
Either side has no seriesCompatible
RetailRetail, MAAX, Swan
MAAXRetail, MAAX, Collection, Professional
Collection / ProfessionalMAAX, Collection, Professional
SwanSwan, Retail only

Brand / Family Rules

  • Same brand: family must also match (if both products have a family)
  • Neptune ↔ Maax: cross-brand compatibility is allowed
  • w&b family: only matches other w&b products
  • utile / nextile wall families have specific base family requirements

Overrides (Whitelist / Blacklist)

Administrators can add entries to the compatibility_overrides table to force two SKUs to always be shown as compatible (whitelist) or never compatible (blacklist), regardless of what the rules compute. Overrides are bidirectional — they apply whether you search A→B or B→A.

9. Data Flow

Here is how data moves through the system from Salsify to a compatibility result:

  1. Salsify publishes a product export and calls POST /api/salsify/webhook with the URL of the Excel file.
  2. The API downloads the Excel file from S3, parses each worksheet (one per product category), and upserts every row into the products database table.
  3. Compatibility is recomputed for all products in the background. Results are stored in the product_compatibility table.
  4. A query hits GET /api/compatible/{sku}. The API reads from the pre-computed table, applies any active overrides, and returns the result.

Database tables:

TablePurpose
productsAll product data with a JSON attributes column
product_compatibilityPre-computed compatible pairs
compatibility_overridesManual whitelist / blacklist entries
sync_statusesSalsify sync history (shown on the Sync History page)
