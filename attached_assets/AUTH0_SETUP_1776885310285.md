# Auth0 Setup Guide

## Overview
Yes, you need **TWO separate applications** in Auth0:

1. **Regular Web Application** - For user authentication (login/logout)
2. **Machine-to-Machine (M2M) Application** - For the Management API (password changes)

## Step-by-Step Setup

### Step 1: Create Regular Web Application (User Login)

1. Go to your Auth0 Dashboard → Applications → Create Application
2. Name: `Password Manager Web App` (or any name you prefer)
3. Choose: **Regular Web Applications**
4. Click **Create**

**Configure the application:**
1. Go to the **Settings** tab
2. Copy the **Client ID** → This is your `AUTH0_WEB_CLIENT_ID`
3. Copy the **Client Secret** → This is your `AUTH0_WEB_CLIENT_SECRET`
4. Scroll to **Application URIs** section and add BOTH dev and production URLs:
   - **Allowed Callback URLs**:
     ```
     https://auth-0-password-manager--ABG-Web-ops.replit.app/callback, https://4545ec6c-6277-49fd-92b3-4af9b2869f00-00-2n45yt0n9s2fe.riker.replit.dev/callback
     ```
   - **Allowed Logout URLs**:
     ```
     https://auth-0-password-manager--ABG-Web-ops.replit.app, https://4545ec6c-6277-49fd-92b3-4af9b2869f00-00-2n45yt0n9s2fe.riker.replit.dev
     ```
   - **Allowed Web Origins**:
     ```
     https://auth-0-password-manager--ABG-Web-ops.replit.app, https://4545ec6c-6277-49fd-92b3-4af9b2869f00-00-2n45yt0n9s2fe.riker.replit.dev
     ```
5. Click **Save Changes**

---

### Step 2: Create Machine-to-Machine Application (Management API)

1. Go to Applications → Create Application
2. Name: `Password Manager Management API` (or any name you prefer)
3. Choose: **Machine to Machine Applications**
4. Click **Create**

**Configure the application:**
1. Select the **Auth0 Management API** from the dropdown
2. Under **Permissions**, select these scopes:
   - `read:users` - Required to search and view users
   - `update:users` - Required to change passwords
3. Click **Authorize**
4. Go to the **Settings** tab
5. Copy the **Client ID** → This is your `AUTH0_MGMT_CLIENT_ID`
6. Copy the **Client Secret** → This is your `AUTH0_MGMT_CLIENT_SECRET`

---

### Step 3: Get Database Connection Name

1. Go to Authentication → Database
2. Find your database connection (usually `Username-Password-Authentication`)
3. Copy the exact name → This is your `AUTH0_CONNECTION`

---

### Step 4: Get Auth0 Domain

1. Look at the top of your Auth0 Dashboard
2. Your domain will be something like:
   - `your-tenant.auth0.com`
   - `your-tenant.us.auth0.com`
   - `your-tenant.eu.auth0.com`
3. Copy this domain (without `https://`) → This is your `AUTH0_DOMAIN`

---

## Secrets Summary

You should now have all 7 secrets configured in Replit:

✅ `AUTH0_DOMAIN` - Your Auth0 tenant domain  
✅ `AUTH0_WEB_CLIENT_ID` - From Regular Web Application  
✅ `AUTH0_WEB_CLIENT_SECRET` - From Regular Web Application  
✅ `AUTH0_MGMT_CLIENT_ID` - From M2M Application  
✅ `AUTH0_MGMT_CLIENT_SECRET` - From M2M Application  
✅ `AUTH0_CONNECTION` - Database connection name  
✅ `SESSION_SECRET` - Random string for session encryption  

---

## Testing Your Setup

Once all secrets are configured:

1. Visit your Replit app URL
2. Click "Login" or access any protected page
3. You'll be redirected to Auth0 for login
4. After successful login, you'll be redirected back to your app
5. You should see your email in the navigation bar
6. You can now search for users and change passwords
7. All password changes will be logged in the Audit Logs page

---

## Why Two Applications?

- **Regular Web Application**: Uses OAuth 2.0 Authorization Code flow for secure user authentication with browser redirects
- **M2M Application**: Uses Client Credentials flow for backend-to-backend API calls (Management API)

This separation follows security best practices by keeping user authentication separate from API operations.
