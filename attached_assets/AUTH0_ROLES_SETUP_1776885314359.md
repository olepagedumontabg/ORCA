# Auth0 Role-Based Access Control Setup

This application uses **Auth0 roles** to control who can access the password manager. Only users with the `password-admin` role can log in.

---

## Step-by-Step Setup Guide

### Step 1: Create the Password Admin Role

1. Go to **Auth0 Dashboard** → **User Management** → **Roles**
2. Click **Create Role**
3. Configure the role:
   - **Name**: `password-admin`
   - **Description**: `Users who can access the password management application`
4. Click **Create**

---

### Step 2: Create an Auth0 Action to Enforce Roles

1. Go to **Actions** → **Library** → **Build Custom**
2. Click **Create Action**
3. Configure:
   - **Name**: `Enforce Password Admin Role`
   - **Trigger**: `Login / Post Login`
   - **Runtime**: Node 18 (Recommended)
4. Replace the code with:

```javascript
/**
 * Handler that will be called during the execution of a PostLogin flow.
 *
 * @param {Event} event - Details about the user and the context in which they are logging in.
 * @param {PostLoginAPI} api - Interface whose methods can be used to change the behavior of the login.
 */
exports.onExecutePostLogin = async (event, api) => {
  // Only check for the Password Manager application
  const passwordManagerClientId = event.secrets.PASSWORD_MANAGER_CLIENT_ID;
  
  // Skip check if this login is for a different application
  if (event.client.client_id !== passwordManagerClientId) {
    return;
  }
  
  // Get user roles
  const userRoles = event.authorization?.roles || [];
  const requiredRole = 'password-admin';
  
  // Check if user has the required role
  if (!userRoles.includes(requiredRole)) {
    api.access.deny(
      `Access denied: You must have the '${requiredRole}' role to access this application. Please contact your administrator.`
    );
  }
};
```

5. Click **Deploy**

---

### Step 3: Add Secret to Action

1. In the Action editor, click the **Secrets** icon (🔒) in the left sidebar
2. Click **Add Secret**
3. Add:
   - **Key**: `PASSWORD_MANAGER_CLIENT_ID`
   - **Value**: Your Web Application Client ID (the value of your `AUTH0_WEB_CLIENT_ID` secret)
4. Click **Create**

**To find your Client ID:**
- Check your Replit Secrets panel for `AUTH0_WEB_CLIENT_ID`
- Or go to Auth0 Dashboard → Applications → Your Web App → Settings

---

### Step 4: Add Action to Login Flow

1. Go to **Actions** → **Flows** → **Login**
2. Find your `Enforce Password Admin Role` action in the right sidebar under **Custom**
3. **Drag and drop** it into the flow between "Start" and "Complete"
4. Click **Apply**

---

### Step 5: Assign Roles to Users

Now assign the `password-admin` role to users who should have access:

**Option A: Via Dashboard (Manual)**

1. Go to **User Management** → **Users**
2. Click on a user
3. Go to the **Roles** tab
4. Click **Assign Roles**
5. Select `password-admin`
6. Click **Assign**

**Option B: During User Creation (Recommended)**

Set up an Action to auto-assign the role based on email domain:

1. Create a new Action with trigger **Pre User Registration**
2. Use this code:

```javascript
exports.onExecutePreUserRegistration = async (event, api) => {
  const emailDomain = event?.user?.email?.split('@')?.[1] || '';
  const allowedDomains = ['yourcompany.com', 'partnerdomain.com'];
  
  // Only allow signups from approved domains
  if (!allowedDomains.includes(emailDomain)) {
    api.access.deny(`Email domain "${emailDomain}" is not authorized for this application.`);
  }
  
  // Role will be assigned in Post Registration Action
};
```

3. Create another Action with trigger **Post User Registration**:

```javascript
exports.onExecutePostUserRegistration = async (event, api) => {
  const ManagementClient = require('auth0').ManagementClient;
  
  const management = new ManagementClient({
    domain: event.secrets.AUTH0_DOMAIN,
    clientId: event.secrets.AUTH0_MGMT_CLIENT_ID,
    clientSecret: event.secrets.AUTH0_MGMT_CLIENT_SECRET,
  });
  
  try {
    // Get the password-admin role
    const roles = await management.roles.getAll();
    const passwordAdminRole = roles.data.find(r => r.name === 'password-admin');
    
    if (passwordAdminRole) {
      // Assign role to new user
      await management.users.assignRoles(
        { id: event.user.user_id },
        { roles: [passwordAdminRole.id] }
      );
    }
  } catch (error) {
    console.error('Failed to auto-assign role:', error);
  }
};
```

4. Add these secrets to the Post Registration Action:
   - `AUTH0_DOMAIN` - Your Auth0 domain
   - `AUTH0_MGMT_CLIENT_ID` - Your M2M app client ID
   - `AUTH0_MGMT_CLIENT_SECRET` - Your M2M app client secret

## Troubleshooting

### "Access denied" for users with the role

**Possible causes:**
1. Action isn't deployed → Check Actions → Library, ensure it shows "Deployed"
2. Action isn't in the flow → Check Actions → Flows → Login
3. Wrong Client ID in secrets → Verify `PASSWORD_MANAGER_CLIENT_ID` matches `AUTH0_WEB_CLIENT_ID`

**Debug steps:**
1. Go to **Monitoring** → **Logs**
2. Find the failed login attempt
3. Click to view details
4. Look for Action execution logs

### Role assignments not working

1. Verify the role name is exactly `password-admin` (case-sensitive)
2. Check user's roles: User Management → Users → [User] → Roles tab
3. Ensure RBAC is enabled: Settings → API → [Your API] → RBAC Settings

### Action not executing

1. Ensure the Action is **Deployed** (not Draft)
2. Verify it's added to the **Login** flow
3. Check that the `PASSWORD_MANAGER_CLIENT_ID` secret is set

## Advanced: Restrict by Email Domain

To only allow users from specific email domains:

Update your **Post Login Action**:

```javascript
exports.onExecutePostLogin = async (event, api) => {
  const passwordManagerClientId = event.secrets.PASSWORD_MANAGER_CLIENT_ID;
  
  if (event.client.client_id !== passwordManagerClientId) {
    return;
  }
  
  // 1. Check email domain
  const emailDomain = event?.user?.email?.split('@')?.[1] || '';
  const allowedDomains = ['yourcompany.com', 'partnerdomain.com'];
  
  if (!allowedDomains.includes(emailDomain)) {
    api.access.deny(`Access denied: Email domain "${emailDomain}" is not authorized.`);
    return;
  }
  
  // 2. Check role
  const userRoles = event.authorization?.roles || [];
  const requiredRole = 'password-admin';
  
  if (!userRoles.includes(requiredRole)) {
    api.access.deny(`Access denied: Missing required '${requiredRole}' role.`);
  }
};
```

## Architecture Summary

```
User Login Attempt
    ↓
Auth0 Authentication
    ↓
Post-Login Action Executes
    ↓
Check: Is this the Password Manager app?
    ↓ Yes
Check: Does user have 'password-admin' role?
    ↓ No → Access Denied
    ↓ Yes
Application Access Granted ✅
```

## Security Best Practices

✅ **Use specific Client ID check** - Ensures role requirement only applies to this app  
✅ **Require roles, not permissions** - Simpler to manage for this use case  
✅ **Combine with email domain restrictions** - Add extra layer for corporate use  
✅ **Use Management API carefully** - Only use in trusted Actions  
✅ **Monitor Auth0 logs** - Regularly check for unauthorized access attempts  
✅ **Review role assignments** - Periodically audit who has access
